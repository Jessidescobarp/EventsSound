# Decisions

ADR-style log. Each entry: decision, reason. Full reasoning lives in the linked OpenSpec artifacts.

1. **Render for backend (Docker web service) and frontend (static site).** One provider, free tier, simple Blueprint. Fallback: a VM with Docker Compose. See [design.md](../openspec/changes/walking-skeleton-and-deploy/design.md).
2. **Neon Postgres, not Render Postgres.** As of 2026-10-09 (unverified; verify at deploy time): free Render Postgres expires after 30 days, while the Neon free tier supports pgvector and does not expire.
3. **Spanish UI, English code and docs.** Target users are Spanish speakers; the codebase stays in English.
4. **Vertical-slice phasing.** Ship a thin end-to-end agent early and deploy the skeleton in P0, instead of building layer by layer. See [exploration](../openspec/changes/tfm-phased-mvp/exploration.md).
5. **Chained PRs under 400 lines.** Keeps reviews small. PR 1 was split into 1a and 1b. See [tasks.md](../openspec/changes/walking-skeleton-and-deploy/tasks.md).
6. **OpenSpec as the artifact store.** Artifacts are versioned in git under `openspec/`.
7. **Synthetic data only.** Avoids privacy issues and keeps the demo reproducible.
8. **Liveness vs readiness health.** `/health` never touches the DB (so Render does not restart on a database blip); `/health/db` checks connectivity.
9. **Prices computed by code, not by the LLM.** Makes quotes verifiable by an oracle and limits prompt-injection impact.
10. **Migrations run in the start script.** Free Render instances have no pre-deploy hook (verified 2026-10-10, see [apply-progress-pr4.md](../openspec/changes/walking-skeleton-and-deploy/apply-progress-pr4.md)).
11. **Hybrid local development.** Only Postgres runs in Docker; backend (`uvicorn --reload`) and frontend (Vite) run natively for hot reload, driven by `scripts/dev.ps1`. The containerized stack (`docker compose --profile app up --build`) stays as the production-like check. Tradeoffs: requires uv and Node locally and the scripts are PowerShell-first (Windows target); in exchange, no image rebuilds per edit and no bind-mount file-watching issues on Docker Desktop. See [proposal](../openspec/changes/local-dev-workflow/proposal.md).
12. **Whole COP pesos in `*_cop` BIGINT columns; flat `bookings`; guarded seed.** COP has no practical minor unit, so `*_cents` columns would store a meaningless factor of 100: money is whole pesos in `*_cop` BIGINT (never float or `Numeric`), rates are basis points in `*_bps`. Bookings are one flat row per item per booking (`booking_code`, `item_code` FK to `equipment_items.code`) instead of a header plus `booking_items`: it mirrors the domain `Booking` and keeps the availability query a single-table select; a header table can be added later by expand/contract. The synthetic seed is a manual, idempotent upsert keyed by stable codes, never a migration: it needs `--confirm`, refuses non-local hosts (URL host, `?host=`, `?hostaddr=`, `?service=` and the libpq `PG*` variables) and `APP_ENV=production` unless `ALLOW_REMOTE_SEED=1`, checks that the database is at the migration head, and only seeds its fixed-date demo bookings on local non-production targets. See [design.md](../openspec/changes/quote-domain-core/design.md).
13. **Availability is computed in the domain; Swagger is public.** Availability is a pure domain function over the bookings the use case loads: the repository returns the bookings intersecting `[start - buffer, end + buffer)` and the domain computes peak concurrency with the 2-hour buffer, so the rule is testable without a database and the SQL stays a plain range select. There is deliberately no HTTP availability route yet. Swagger UI (`/docs`) and `/openapi.json` are public in production (developer decision, 2026-10-12): the API is read-only with synthetic data, and a browsable schema is part of the demo. ReDoc stays off. See [design.md](../openspec/changes/quote-domain-core/design.md).
14. **Keyword search first, tools as an allowlisted executor.** Equipment search is deterministic keyword scoring (accent and plural folding, a small Spanish synonym map, idf weighting, ties by code) behind a batched `EquipmentSearch` port; vector retrieval plugs into the same port later and falls back to keywords. The three tools (`buscar_equipamiento`, `consultar_disponibilidad`, `calcular_precio`) validate arguments with strict Pydantic models (`extra="forbid"`, no coercion, no price fields) and return closed-set errors with fixed messages. The graph, not the model, chooses the tool; a model-supplied name outside the allowlist runs nothing. See [design.md](../openspec/changes/quote-agent/design.md).
